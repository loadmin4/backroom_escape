# 백룸 탈출: 강화학습으로 flag 빨리 찾기

무한히 펼쳐진 백룸. 모든 방은 똑같이 생겼고 상/하/좌/우에 문이 있다.
어딘가의 방에 flag 가 있고, 그 방에 들어가면 탈출한다. 회차마다 시작점과 flag 위치가 바뀐다.
에이전트가 **flag 를 최대한 빨리 찾도록** PPO 로 학습시킨다.

```
agent=bayes hint=sound                    S = 시작 방, F = flag, @ = 에이전트
. . . . . . . . . . . . .                 숫자 = 지나온 방에서 들은 소리 크기(0~9)
. . . . . . . . . . . . .
. . . . . . S . . . . . .
. . . . . . 1 . . . . . .
. . . . . . 2 3 4 @ . . .
                                          탈출 성공!  걸음 수 = 12
```

## 먼저 짚어야 할 점: 방이 전부 똑같다면 무엇을 배울 수 있나?

학습을 설계하기 전에 문제를 정확히 봐야 한다. 결론부터 말하면 **방이 정말 전부 똑같고 아무 단서도 없다면,
어떤 모델도 체계적인 탐색(나선 탐색)보다 빨라질 수 없다.** 그래서 이 저장소는 두 가지 모드를 둔다.

1. **시작점이 바뀌는 것은 아무 영향이 없다.**
   모든 방이 똑같으니 세계는 어느 방에서 봐도 같다(평행이동 대칭). 에이전트가 쓸 수 있는 건
   "시작점에서 몇 칸 움직였나"라는 상대 좌표뿐이고, 절대 위치는 관측할 수도 없고 알아도 쓸모가 없다.
   중요한 것은 **flag 가 시작점 기준으로 어디쯤 있는가의 분포**다.

2. **flag 가 정말 "무한한 공간 어디든" 있을 수 있다면 평균 탐색 시간은 무한이다.**
   그래서 분포를 가정해야 한다. 기본값은 "시작점에서 가로·세로 6칸 이내(13×13 영역, 후보 168개 방)에 균등"이다.
   (`--flag-range` 로 바꿀 수 있다.)

3. **단서가 없으면(`hint=none`) 이론적 하한이 이미 정해져 있다.**
   한 걸음에 확인할 수 있는 새 방은 최대 하나다. 후보 n 개가 균등하면 평균 걸음 수는 **(n + 1) / 2 = 84.5** 보다
   작아질 수 없고, 같은 방을 다시 가지 않는 나선 탐색이 이미 이 값을 달성한다.
   학습된 모델이 할 수 있는 최선은 이 나선 탐색을 다시 발견하는 것이다.

4. **그래서 flag 가 무언가 신호를 내야 한다(`hint=sound`).**
   flag 가 소리를 내고, 각 방에서 `1 / (1 + 거리) + 잡음` 크기로 들린다고 하자. 먼 곳에서는 잡음에 묻히지만
   여러 방에서 들은 값을 모으면 방향을 추론할 수 있다. 이때 학습된 모델은 나선 탐색보다 **몇 배 빨라진다.**

실제로 풀고 싶은 문제에 "방마다 미세하게 다른 무언가"(소리, 냄새, 방 무늬, 조명 등)가 있다면
그것을 관측에 넣는 것이 핵심이다. 그런 단서가 없다면 학습 대신 나선 탐색을 쓰면 된다.

## 결과

2000 회차(같은 seed → 모든 에이전트가 똑같은 시작점/flag 배치)에서 평가. 걸음 수는 flag 를 찾기까지의 걸음이며
실패는 250(최대 걸음)으로 계산한다.

**기준 에이전트** (`python evaluate.py --hint none` / `--hint sound`)

| 에이전트 | hint=none 성공률 | hint=none 평균 걸음 | hint=sound 성공률 | hint=sound 평균 걸음 |
|---|---|---|---|---|
| random-walk | 28.1% | 200.6 | 28.1% | 200.6 |
| spiral | 100% | **84.5** | 100% | 84.5 |
| bayes-search | 100% | 85.9 | 100% | **22.4** |
| (단서 없을 때 이론적 하한) | | 84.5 | | |

**PPO 학습 중 로그** (CPU 4코어에서 두 모드를 동시에 학습, 모드당 약 2,300 걸음/초)

| 학습 걸음 수 | hint=none 성공률 / 평균 걸음 | hint=sound 성공률 / 평균 걸음 |
|---|---|---|
| 8만 (시작 직후) | 34% / 194 | 28% / 202 |
| 41만 | 68% / 139 | 99.8% / 48 |
| 250만~260만 | 91% / 104 | 100% / **24** |
| 400만 (학습 끝) | 94% / 95 | 100% / 23 |

**학습이 끝난 모델 평가** (400만 걸음, `python evaluate.py --checkpoint checkpoints/ppo_<hint>.pt`, 위와 같은 2000 회차)

| 모드 | PPO 성공률 | PPO 평균 / 중앙값 / p90 | 비교 |
|---|---|---|---|
| sound | 100% | **23.6** / 22 / 40 | 베이즈 탐색 22.4, 나선 84.5 |
| none | 93.8% | 98.5 / 86 / 208 | 나선 84.5 (이론적 하한) |

- sound 모드: 250만 걸음 만에 나선 탐색(84.5)보다 **3.5배 빠르고**, 소리 모델을 미리 아는 베이즈 탐색(22.4)에 거의 도달한다.
- none 모드: 중앙값(86)은 나선 탐색과 비슷하지만 약 6% 회차는 갔던 곳 근처를 맴돌다 250 걸음 안에 못 찾는다. 단서가 없으니 어차피 84.5 보다 빨라질 수 없고, 이 경우엔 학습보다 나선 탐색이 낫다.
- 로그 값은 학습 중 확률적으로 행동을 뽑은 결과다. 학습이 끝난 뒤 `evaluate.py` 로 같은 2000 회차에서 기준선과 비교하면 된다.

- **random-walk**: 아무 문이나 연다.
- **spiral**: 사각 나선으로 바깥쪽으로 훑는다. 단서가 없을 때의 최선.
- **bayes-search**: flag 의 사전분포와 소리 모델을 *미리 알고* 사후확률을 계산하는 모델 기반 탐색. 강한 참고선.
- **ppo**: 이 저장소에서 학습한 신경망. 사전분포도 소리 모델도 모른 채 경험만으로 배운다.

## 환경 설계

| 항목 | 내용 |
|---|---|
| 행동 | 위/오른쪽/아래/왼쪽 문 중 하나 (4개) |
| 보상 | 한 걸음마다 -0.01, flag 방에 들어가면 +1 (빨리 찾을수록 보상이 큼) |
| 종료 | flag 방 도착(성공) 또는 250 걸음(실패) |
| 관측: 기억 지도 | 에이전트 중심 25×25 창. 채널 = 가 본 방(분필 표시), 시작 방, 그 방에서 들은 소리의 평균 |
| 관측: 벡터 | 시작점 기준 상대 좌표, 남은 시간, 지금 들리는 소리, 주변 5×5 칸의 정확한 값 |
| 정책 | 작은 CNN + MLP (23만 파라미터), PPO |

에이전트는 월드 좌표도 flag 위치도 보지 못한다. 볼 수 있는 건 **자기가 지나온 길**과 (sound 모드라면) **들은 소리**뿐이다.
무한한 격자는 원환(torus) 배열에 접어서 기억하는데, 배열 한 변을 `max_steps + view_radius + 1` 로 잡아서
관측 창 안에서 서로 다른 방이 겹치는 일이 없게 했다 (`tests/test_env.py` 에서 진짜 무한 격자와 비교해 검증).

## VS Code + GPU 로 학습·평가하기 (윈도우)

### 준비물

- **NVIDIA GPU 와 최신 드라이버** ([nvidia.com/drivers](https://www.nvidia.com/drivers)).
  CUDA Toolkit 은 따로 설치할 필요가 없다 (PyTorch 안에 들어 있다). GPU 가 없으면 자동으로 CPU 로 학습한다.
- **Python 3.10 ~ 3.12** ([python.org](https://www.python.org/downloads/windows/)). 설치 첫 화면에서 **"Add python.exe to PATH"** 체크.
- **VS Code**. 폴더를 열면 Python 확장 설치를 권하는 알림이 뜨니 설치한다.

### 1. 폴더 열기

VS Code → 파일 → 폴더 열기 → `train.py` 가 들어 있는 `backroom_escape` 폴더.
"이 폴더에 있는 파일의 작성자를 신뢰합니까?" 가 나오면 **신뢰**를 누른다 (그래야 작업/실행 설정이 동작한다).

### 2. 환경 설치 (처음 한 번)

**터미널 → 작업 실행... → `1. 환경 설치 (GPU 자동 감지)`**

`scripts/setup_windows.ps1` 이 다음을 한다.

1. `.venv` 가상환경을 만든다.
2. `nvidia-smi` 로 드라이버 버전을 보고 PyTorch 를 고른다: 드라이버 580 이상이면 CUDA 13.0, 아니면 CUDA 12.6 빌드
   (RTX 50 시리즈는 드라이버 580 이상 필요). GPU 버전은 2~3GB 라 몇 분 걸린다.
3. numpy, tensorboard, pytest 를 설치하고, 마지막에 GPU 인식 여부와 CPU/GPU 학습 속도를 측정해 보여 준다.

끝나면 **Ctrl+Shift+P → `Python: Select Interpreter` → `.venv`** 를 고른다 (오른쪽 아래 상태 표시줄에 `.venv` 가 보이면 된다).

### 3. 학습

**실행 및 디버그(Ctrl+Shift+D)** → 위쪽 목록에서 구성을 고르고 **Ctrl+F5**(디버깅 없이 실행).
F5 로 실행하면 중단점을 걸어 코드를 한 줄씩 볼 수 있지만 조금 느리다.

| 구성 | 하는 일 |
|---|---|
| 학습: 빠른 동작 확인 (20만 걸음) | 설치가 잘 됐는지 몇 분 만에 확인. `checkpoints/ppo_quick.pt` |
| 학습: sound (소리 힌트, 400만 걸음) | flag 소리를 듣고 찾도록 학습. `checkpoints/ppo_sound.pt` |
| 학습: none (힌트 없음, 400만 걸음) | 방이 전부 똑같을 때. `checkpoints/ppo_none.pt` |
| 학습: sound + none 동시에 | 위 두 개를 한꺼번에 |
| 평가: 모델 고르기 | 고른 모델을 랜덤 / 나선 / 베이즈 탐색과 같은 2000 회차에서 비교 |
| 시각화: 모델 고르기 | 고른 모델의 한 회차를 터미널에 애니메이션으로 |

학습 로그 첫 줄에 `device: cuda (GPU 이름)` 이 보이면 GPU 로 학습 중이다. `device: cpu` 라면 아래 문제 해결을 본다.

### 4. 학습 상황 실시간으로 보기

**① 터미널 로그** (약 8만 걸음마다 한 줄)

```
[##########----------]  50.0% 남은 시간  14.2분 |  2,000,000 steps  2350/s | success= 99.8% mean_steps=  27.1 lr=1.50e-04 entropy=0.41 v_loss=0.0052
```

진행률 막대, 남은 시간, 성공률, 평균 걸음 수, 현재 학습률(lr)이 나온다.

**② TensorBoard 그래프** (약 8천 걸음마다 갱신, 5초마다 자동 새로고침)

1. **터미널 → 작업 실행... → `3. TensorBoard 열기`**
2. VS Code 안에서 보려면 **Ctrl+Shift+P → `Simple Browser: Show` → `http://localhost:6006`**
   (웹 브라우저로 열어도 된다)

| 그래프 | 의미 |
|---|---|
| `episode/mean_steps` | flag 를 찾기까지 평균 걸음 수. **내려가야 한다** |
| `episode/success_rate` | 250 걸음 안에 찾은 비율(%). 100 에 가까워져야 한다 |
| `train/learning_rate` | 현재 학습률. 3e-4 에서 시작해 학습이 끝날 때 0 으로 선형 감소 |
| `train/progress_percent` | 이번 학습의 진행률(%) |
| `loss/entropy` | 행동의 무작위성. 내려갈수록 정책이 확신을 가진다 |
| `loss/value`, `loss/policy` | 신경망 손실 |
| `speed/steps_per_sec` | 초당 학습 걸음 수 (GPU 효과 확인용) |

학습할 때마다 `runs/` 에 새 기록이 생기므로 여러 번의 학습(예: 처음 학습과 이어서 학습)을 한 그래프에서 겹쳐 비교할 수 있다.

### 문제 해결

| 증상 | 해결 |
|---|---|
| 로그에 `device: cpu` | 작업 `2. 설치·GPU 확인 + 학습 속도 측정` 을 실행하고 안내를 따른다 (드라이버 없음 / CPU 전용 PyTorch 설치됨 등) |
| `no kernel image is available` 오류 | GPU 가 너무 새것이라 CUDA 12.6 빌드가 지원하지 않는 경우. 드라이버를 580 이상으로 올리고 설치 작업을 다시 실행 |
| 터미널을 열 때 `Activate.ps1 ... 스크립트를 실행할 수 없으므로` | PowerShell 에서 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 한 번 실행 (학습·평가 실행에는 영향 없음) |
| `'torch' 패키지를 찾을 수 없습니다` | 메시지가 원인을 알려 준다. ① 환경 설치 작업을 아직 안 했거나 중간에 실패함 → 설치 작업 다시 실행 ② 다른 파이썬으로 실행함(에디터 오른쪽 위 ▷ 버튼 등) → 실행 및 디버그의 구성으로 실행하거나 인터프리터를 `.venv` 로 ③ 압축을 풀어 생긴 바깥 폴더를 엶 → `train.py` 가 있는 폴더를 연다 |
| GPU 사용률이 낮다 | 정상이다. 신경망이 작고 백룸 환경은 CPU(numpy)에서 돌기 때문. GPU 는 역전파를 빠르게 해 준다. 더 많이 쓰려면 `--n-envs 256` (한 번에 모으는 경험이 늘어 학습 양상이 달라질 수 있음) |

## 명령어로 실행하기 (모든 OS)

```bash
pip install -r requirements.txt   # GPU 를 쓰려면 먼저 CUDA 버전 PyTorch 를 설치 (pytorch.org 참고)

# 학습. GPU 가 있으면 자동으로 쓴다 (--device cpu 로 끌 수 있음). 결과는 checkpoints/ppo_<hint>.pt
python train.py --hint sound --steps 4000000
python train.py --hint none  --steps 4000000

# 평가: 학습된 모델 vs 랜덤 / 나선 / 베이즈 탐색
python evaluate.py --checkpoint checkpoints/ppo_sound.pt
python evaluate.py --checkpoint checkpoints/ppo_none.pt

# 한 회차를 터미널에 그려 보기
python play.py --checkpoint checkpoints/ppo_sound.pt --animate
python play.py --agent spiral --hint none

# 설치·GPU 확인, 학습 곡선, 테스트
python check_gpu.py
tensorboard --logdir runs
pytest
```

학습 중에는 10 업데이트(약 8만 걸음)마다 이런 로그가 찍히고, 그때마다 체크포인트를 덮어쓴다.
중간에 멈춰도 그때까지 학습된 모델이 `checkpoints/ppo_<hint>.pt` 에 남는다.

```
[##########----------]  50.0% 남은 시간  14.2분 |  2,000,000 steps  2350/s | success= 99.8% mean_steps=  27.1 lr=1.50e-04 entropy=0.41 v_loss=0.0052
```

| 값 | 의미 |
|---|---|
| `남은 시간`, `/s` | 이번 학습이 끝날 때까지 예상 시간, 초당 학습 걸음 수 (CPU 4코어에서 약 2,300~3,500) |
| `lr` | 현재 학습률 (학습이 진행될수록 0 으로 줄어든다) |
| `success` | 직전 8만 걸음 동안 끝난 회차 중 flag 를 찾은 비율 |
| `mean_steps` | 그 회차들의 평균 걸음 수. **이 값이 내려가는 것이 학습의 목표** |
| `entropy` | 행동의 무작위성. 내려갈수록 정책이 확신을 갖는다 |

`train.py` 주요 옵션:

| 옵션 | 기본값 | 의미 |
|---|---|---|
| `--hint` | `sound` | `none`: 방이 전부 똑같음, `sound`: flag 소리가 들림 |
| `--steps` | 4,000,000 | 총 학습 걸음 수 |
| `--device` | `auto` | `auto`(GPU 있으면 GPU) / `cuda` / `cpu` |
| `--flag-range` | 6 | flag 는 시작점에서 가로/세로 이 칸 수 이내 |
| `--max-steps` | 250 | 한 회차 최대 걸음 수 |
| `--sound-noise` | 0.1 | 소리 잡음의 표준편차 (클수록 어려움) |
| `--n-envs` | 64 | 동시에 돌리는 회차 수 |
| `--out` | `checkpoints/ppo_<hint>.pt` | 체크포인트 경로 |
| `--logdir` | `runs` | TensorBoard 기록 폴더 (`""` 이면 기록 안 함) |

## 파일 구조

```
backroom/
  env.py         백룸 환경 (여러 회차를 동시에 돌리는 벡터 환경)

  model.py       정책·가치 신경망, 체크포인트 저장/불러오기
  ppo.py         PPO 학습 루프
  evaluation.py  같은 배치의 회차들에서 에이전트 비교

```

## 더 해볼 만한 것

- **단서 바꾸기**: 소리 대신 "flag 쪽 문에서 바람이 분다(확률적으로 맞는 방향 힌트)", "flag 에 가까울수록 조명이 깜빡인다" 등.
  `BackroomVecEnv._enter` 에서 관측을 만들고 `observe` 의 채널에 넣으면 된다.
- **분포 바꾸기**: 가까운 방일수록 flag 가 있을 확률이 높다면 나선 탐색도 모델도 더 빨라진다.
- **벽/잠긴 문**: 일부 문이 막혀 있으면 미로 탐색 문제가 되고, 기억 지도에 벽 채널을 추가하면 된다.
- **기억 없는 에이전트**: 분필 표시(방문 지도)를 빼면 LSTM/GRU 정책이 스스로 경로를 기억해야 한다.
